# Custom symbols

The tab bar and three toolbar glyphs are custom SF Symbols, generated by
`scripts/make_symbols.swift` into `Sources/Assets.xcassets/*.symbolset`. The set is the
"opus" redesign (2026-09-30), one of three parallel designs (Fable, Opus, Sonnet), now
on trial on Nuri's phone.

```bash
swift scripts/make_symbols.swift Sources/Assets.xcassets
```

Never edit the SVGs by hand.

| Symbol | Drawing | Used by |
|---|---|---|
| `tab.today` | four fingertip bars on the edge (the app icon) | Today tab |
| `tab.history` / `.fill` | a calendar page whose days are session circles | History tab, History empty state |
| `tab.benchmarks` / `.fill` | one max pull, a force peak, under the dashed record line | Benchmarks tab |
| `tab.settings` / `.fill` | an eight-tooth gear | Settings tab |
| `glyph.gauge` | a closed dial, needle swung high (closed so it centres on its pivot) | Today › Live gauge |
| `glyph.export` | the share tray with an arrow leaving it | History › Export |
| `glyph.log` | the History calendar page with a plus where the days go | Consistency › Log a session |

## Drawing rules

- **Speak iOS first, house second.** Each symbol is a picture an iPhone user already
  reads. Bars, session circles and the edge appear only where they are the meaning.
- **One pen.** One line weight, just under SF Regular (7.4 units against a measured
  8.0 to 8.2). Round caps and joins, one knockout gap, one container corner.
- **Weights vary stroke only, scales vary size only** (S 0.8, M 1, L 1.29), the SF rule.
  A catalog without the S scale draws nothing in a toolbar, which asks for Small.
- **Interpolation-compatible.** All nine groups share one command structure, asserted
  by the generator, so Xcode can blend the in-between weights.
- **Fills only.** Lines are filled outlines, holes are reversed contours.
- **Today has no hollow twin.** A hollow finger is a loop, and a loop reads as a session.
  The iOS tab bar shows the `.fill` twin for every tab anyway; hollow forms appear only
  in the iPad sidebar.

## Motion

Each tab's icon plays one effect when that tab is selected, once, never at rest, and
not under Reduce Motion. Today bounces its fingers up one after another, History
drops its page, Benchmarks lifts its curve, Settings turns its gear one revolution.

Three facts, each found by recording the simulator and measuring frames:

1. **Layers need MOTION GROUPS, not just layer classes.** Tagging paths
   `monochrome-N hierarchical-N:primary` makes Xcode report hierarchical layers, and
   `.byLayer` still moves the symbol as one piece. Apple's exported templates carry a
   `<style>` block giving each layer `-sfsymbols-motion-group:N`; without it every layer
   lands in one group. The generator writes that block, and group order is the order
   layers animate. The per-symbol layer split is the `layer:` closure in its table.
2. **The tab bar ignores SwiftUI's `.symbolEffect` on a `Tab` label**, value-triggered
   and continuous alike: a looping pulse recorded as a single unchanged frame over five
   seconds. The bar draws each item with plain `UIImageView`s, two or three copies per
   tab, so `TabBarSymbolEffects` finds them by symbol name and calls the public
   `addSymbolEffect`. The name match reads `UIImage.description`, which is debug text,
   so it fails closed: if iOS rewords it, tabs stop animating and nothing else changes.
3. **The three toolbar glyphs do not animate.** Each opens a sheet or cover the instant
   it is tapped, so an effect would play underneath it. Toolbar items also ignore
   SwiftUI's `.symbolEffect`.

`UITests/SymbolMotionUITests.swift` taps through every tab for a screen recording; its
header has the recording and frame-extraction commands.

## History

The first custom set (2026-09-28) drew everything from the house vocabulary: a session
grid for History, dial tracks for Settings, an arrow off the edge for Export. Nuri did
not like it, and three designers redrew the set in parallel. The other two sets live
only in that session's scratch folders.
